### **Проблемные места текущего состояния системы**  


| **Проблема** | **Описание** | **Последствия для бизнеса** |  
|--------------|---------------|------------------|  
| **Медленная и ненадежная система хранения данных** | Устаревшая база данных (SQL Server 2008) не справляется с объемами информации (сотни ТБ). Данные обрабатываются медленно, а поддержка Microsoft прекращена. | Отчеты готовятся часами, интеграция новых направлений (банк, фармацевтика) затягивается на месяцы. Риск потери данных и кибератак из-за устаревшей защиты. |  
| **Зависимость от «узкого горлышка»** | Все данные и процессы завязаны на одну систему. Любые изменения (например, для финтеха) требуют переделки всей системы. | Новые продукты и сервисы внедряются крайне медленно. Компания теряет клиентов из-за невозможности быстро адаптироваться к рынку. |  
| **Риск утечки медицинских данных** | Конфиденциальные данные пациентов (истории болезней, исследования) хранятся в той же системе, что и финансовая аналитика. | Штрафы за нарушение 152ФЗ, потеря репутации, судебные иски. |  
| **Медленные и сложные отчеты** | Для создания отчетов сотрудники вручную «собирают» данные из разных источников. Нет инструментов для автоматизации. | Аналитики тратят 80% времени на подготовку данных вместо анализа. Решения принимаются на устаревшей информации. |  
| **Устаревший интерфейс для сотрудников** | Программа для работы с данными (Power Builder) выглядит как ПО 2000-х годов: нет мобильной версии, частые ошибки, сложный интерфейс. | Сотрудники клиник тратят на рутинные задачи в 3–4 раза больше времени. Рост числа ошибок при вводе данных. |  
| **Дорогая и неповоротливая аналитика** | Каждый новый отчет в Power BI требует участия программистов и недель ожидания. | Задержки в получении ключевых метрик (например, отчет о прибыли клиник за месяц готовится 2 недели вместо 2 дней). |

### **Приоритизация проблем (MoSCoW)**  


| **Приоритет** | **Проблема** | **Пояснение для бизнеса** |  
|----------------|--------------|------------------|  
| **Must have** | Медленная и ненадежная система хранения данных | Если DWH выйдет из строя, компания не сможет работать: клиники останутся без данных о пациентах, финтех — без информации по платежам. |  
| **Must have** | Риск утечки медицинских данных | Утечка приведет к штрафам до 4% глобального оборота компании и потере доверия клиентов. |  
| **Must have** | Зависимость от «узкого горлышка» | Невозможно запустить новые продукты (например, интеграцию с фармацевтикой) без перестройки всей системы. |  
| **Should have** | Медленные и сложные отчеты | Задержки в отчетности мешают оперативно принимать решения. Например, невозможно быстро оценить эффективность новой рекламной кампании. |  
| **Should have** | Устаревший интерфейс для сотрудников | Низкая продуктивность медперсонала увеличивает затраты на зарплаты и обслуживание клиентов. |  
| **Could have** | Дорогая и неповоротливая аналитика | Оптимизация сократит затраты на IT-поддержку, но это не критично в краткосроке. |  
| **Won't have** | Полный отказ от Power Builder | На первом этапе можно оставить старый интерфейс для части сотрудников, чтобы не останавливать работу клиник. |
