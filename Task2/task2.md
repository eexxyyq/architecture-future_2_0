### Обоснование разделения на домены

| Принцип                  | Описание                                                                 |
|--------------------------|-------------------------------------------------------------------------|
| **Разделение ответственности** | Каждый домен управляет своей зоной данных и логики. Например, медицинский домен отвечает только за диагнозы и исследования. |
| **Модульность**           | Изменения в финтех-домене (например, внедрение новой платежной системы) не затрагивают медицинский домен. |
| **Масштабируемость**      | Клиентский домен можно масштабировать независимо при росте числа пользователей. |
| **Безопасность**          | Медицинские данные физически изолированы, доступ к ним ограничен ролями (152ФЗ-совместимость). |
| **Интеграции**            | Новые сервисы (например, телемедицина) подключаются через шину Kafka без переделки ядра. |

---

### Потоки данных между доменами

- **Клиентский → Медицинский/Финтех**  
  Данные профиля клиента синхронизируются для создания медицинской карты и открытия счета.

- **Медицинский → BI/AI**  
  Анонимизированные данные исследований передаются для обучения моделей прогнозирования заболеваний.

- **Финтех → BI/AI**  
  Транзакции анализируются для выявления мошенничества (AML) и формирования финансовой отчетности.

- **BI/AI → Все домены**  
  Отчеты и прогнозы (например, спрос на услуги клиник) возвращаются для оптимизации процессов.
